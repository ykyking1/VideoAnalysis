# Worklog — 2026-07-31

Konu: **Temporal + Kafka orkestrasyon zincirinin ilk kez gerçekten çalıştırılması**
(MinIO → Kafka → Temporal → Worker → 6 aktivite → Qdrant). Bu yol worklog_2026-07-29'dan
beri "Doğrulanmayanlar" listesindeydi — sadece `--local` (doğrudan fonksiyon çağrısı)

(Windows, Docker Desktop, CPU-only torch) test edildi.

## Bulunan ve düzeltilen 3 gerçek hata

Hiçbiri daha önce fark edilmemişti çünkü bu yol hiç çalıştırılmamıştı.

1. **`docker-compose.yml`: Kafka'nın host'a açık portu yanlıştı.** Sadece iç ağ
   listener'ı (9092) host'a açılmıştı; host'tan bağlanan süreçlerin (ingest.worker,
   ingest.kafka_consumer) ihtiyaç duyduğu `EXTERNAL` listener (29092) hiç
   yayınlanmıyordu. `.env.example` zaten doğru değeri (`localhost:29092`)
   içeriyordu ama `common/config.py`'nin kod-içi varsayılanı `localhost:9092`
   kalmıştı - üç dosya arasında tutarsızlık. Doğrulandı: eski portla bağlanmayı
   denedim, `kafka:9092` diye host'tan çözülemeyen bir isme yönlendirilip
   timeout'a düştü. Düzeltme: `docker-compose.yml`'e `29092:29092` eklendi,
   `common/config.py`'nin varsayılanı `localhost:29092`'ye çekildi.

2. **`scripts/setup_minio_notifications.py`: kurulu `minio` paketinin gerçek
   `QueueConfig` API'siyle uyumsuzdu.** Kod `QueueConfig(ARN, events,
   config_id=...)` şeklinde çağırıyordu; gerçek imza
   `QueueConfig(events, config_id=None, ..., queue=None)`. ARN, `queue`
   parametresiyle verilmeliydi. `TypeError: got multiple values for argument
   'config_id'` ile patlıyordu - hiç çalıştırılmadığı için hiç fark edilmemişti.

3. **`embed_clips`/`extract_visual_fields`: model soğuk önbellekte ilk kez
   indirilirken heartbeat atılmıyordu.** Gerçek çalıştırmada Qwen3-VL-Embedding-2B
   indirmesi 28 dakika sürdü (bu makinenin ağ hızında); `heartbeat_timeout=10dk`
   aşıldı, Temporal aktiviteyi "tıkandı" sayıp iptal etti, **3 retry'ın hepsi
   aynı şekilde başarısız oldu** (`RETRY_STATE_MAXIMUM_ATTEMPTS_REACHED`) çünkü
   her denemede aynı kod aynı şekilde heartbeat'siz kaldı. Retry, kök nedeni
   (heartbeat eksikliği) çözmüyor. Düzeltme: `_get_embedder()`/`_get_model()`'e
   model çözümleme başlarken bir heartbeat eklendi, `heartbeat_timeout`
   30 dakikaya çıkarıldı (soğuk indirmeyi rahatça tolere etsin diye).
   Doğrulama: aynı testi tekrar çalıştırdım, workflow bu sefer
   `WORKFLOW_EXECUTION_STATUS_COMPLETED` ile bitti.

## Uçtan uca doğrulanan akış

`register_video.py` ile gerçek MinIO'ya (Docker) 10 saniyelik bir test videosu
yüklendi → MinIO'nun Kafka bildirimi tetiklendi → `kafka_consumer.py` mesajı
okuyup `ingest-{video_id}` workflow'unu başlattı → `ingest.worker` (CPU,
`max_concurrent_activities=1`) 6 aktiviteyi sırayla çalıştırdı → proxy
(yazılım fallback, NVENC yoktu), telemetri/pencereleme (2 pencere), embedding
(CPU, bfloat16), YOLO26 (yolo26s, gerçek zamanlı indirildi), caption (vLLM
yerelde yok, zarifçe boş geçildi), `write_clips` → **gerçek Qdrant'a 2 nokta
yazıldı**, payload'lar doğrulandı (`vehicle_count=2`, telemetri alanları
doğru şekilde `None`, `t_start`/`t_end` doğru).

PostgreSQL durum takibi de doğrulandı (`psycopg` eksikti, kuruldu; şema
docker-compose'un init-script mount'uyla otomatik uygulanmış).
