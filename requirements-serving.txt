# vLLM sunucusu — sorgu ayrıştırma (§3.2 madde 1), caption (§3.1 madde 5),
# rerank (§3.2 madde 4) için.
#
# Kurulum:
#
#     pip install -r requirements.txt      # once ana yigin
#     pip install uv
#     uv pip install -r requirements-serving.txt --torch-backend=auto
#
# ⚠️ SÜRÜM GEÇMİŞİ (2026-07, gerçekten yaşandı - Colab + Kaggle'da denendi):
#
# 1) Düz `pip install vllm` en güncel paketi çeker. vLLM v0.20+ "libtorch
#    stable ABI"ye geçti; bu sürümlerin ikili uzantısı CUDA 13 runtime
#    (`libcudart.so.13`) bekliyor. Çoğu ortamda (Colab dahil) bu kütüphane
#    yok -> ImportError. `--torch-backend=auto` bunu ETKİLEMİYOR (sadece
#    torch'un CUDA derlemesini seçiyor, vLLM'in kendi ikilisini değil).
#
# 2) Bunun üzerine `vllm==0.8.3`'e (stable-ABI öncesi son sürüm) sabitledik.
#    Bu da AYRI bir soruna çarptı: 0.8.3 `torch==2.6.0`'a SABİT bağımlı, ve
#    torch 2.6.0 PyPI'dan tamamen kaldırılmış (doğrulandı: `pip index
#    versions torch` en eski 2.9.0'ı gösteriyor). Sonuç ortama göre değişti -
#    Colab'da resolver sessizce eski (0.26.0) sürümde kaldı, Kaggle'da 0.8.3
#    gerçekten kuruldu ama uyumsuz bir torch ile eşleşip
#    "undefined symbol: ...parseSchemaOrName..." ABI hatası verdi.
#
# ÇÖZÜM (PyPI JSON API ile doğrulandı - pypi.org/pypi/vllm/<surum>/json):
# v0.20.0'dan mevcut en güncel sürüme kadar HEPSİ `torch==2.11.0`'a sabit,
# ve bu sürüm hâlâ kurulabilir. Eski bir vLLM sürümüne sabitlemek yerine
# GÜNCEL vLLM'i, ihtiyaç duyduğu torch sürümüyle birlikte AÇIKÇA istiyoruz -
# resolver'ın "zaten kurulu olanı koru" gibi belirsiz davranışına
# bırakmıyoruz:
#
#     uv pip install -q --system "torch==2.11.0" vllm xgrammar --torch-backend=auto
#
# Bu KISMEN doğrulandı (Kaggle'daki ABI hatasının kök nedenini açıklıyor ve
# çözüyor) ama TAM uçtan uca doğrulanmadı - eğer torch==2.11.0 doğru
# kurulursa vLLM'in kendi CUDA13 runtime ihtiyacı da (muhtemelen torch'un
# kendi nvidia-* bağımlılıkları üzerinden) karşılanmış olabilir, ama bu
# tarafımızca çalıştırılıp GÖRÜLMEDİ. Yine `libcudart.so` hatası çıkarsa
# bu ayrı, hâlâ çözülmemiş bir sorun demektir (GitHub #43435, "not planned").
#
# requirements-serving.txt bu yüzden vLLM sürümünü SABİTLEMİYOR - torch'u
# sabitliyor, vLLM'in kendi bağımlılık bildirimi torch'a göre doğru sürümü
# seçsin diye.
#
# Sonucu bize bildirin - bu dosya buna göre güncellenmeli.
#
# Alternatif (hedef makineniz Linux + Docker ise, Colab/Kaggle değilse):
# Docker imajı kendi CUDA runtime'ını taşıyor, pip'in versiyon secimi
# sorununu tamamen atlıyor:
#
#     docker compose --profile gpu up -d vllm
#
# LINUX GEREKTİRİR. vLLM'in resmi platform listesinde Windows YOK. Windows'ta
# üç seçenek: (1) docker compose --profile gpu up -d vllm, (2) WSL2 içine
# kurup host'tan localhost:8000 ile erişin, (3) ayrı Linux sunucuda çalıştırıp
# VLLM_BASE_URL'i ona yönlendirin.
#

# kalır), caption üretilmez, rerank atlanır.
