# vLLM sunucusu — sorgu ayrıştırma (§3.2 madde 1), caption (§3.1 madde 5),
# rerank (§3.2 madde 4) için.
#
# Kurulum:
#
#     pip install -r requirements.txt      # once ana yigin
#     pip install uv
#     uv pip install -r requirements-serving.txt --torch-backend=auto
#
# ⚠️ BİLİNEN, ÇÖZÜLMEMİŞ SORUN (2026-07): vLLM'in v0.20+ sürümleri "libtorch
# stable ABI"ye geçti (v0.22'de başladı, v0.24'te tamamlandı - vLLM release
# notları) ve bu sürümlerin `_C_stable_libtorch` uzantısı CUDA 13 runtime'a
# SABİT bağımlı - `--torch-backend=auto` bunu ETKİLEMİYOR (o sadece torch'un
# kendi CUDA derlemesini seçiyor, vLLM'in kendi ikili uzantısını değil).
# Hata (denendi, gerçekten oluyor):
#
#     ImportError: libcudart.so.13: cannot open shared object file
#
# PyPI'da gerçek/işlevsel bir CUDA 13 runtime paketi de yok
# (`nvidia-cuda-runtime-cu13` sadece sürüm 0.0.1 - boş bir yer tutucu).
# vLLM'in kendi issue'su bu durumu "not planned" diye kapattı:
# github.com/vllm-project/vllm/issues/43435
#
# ÇÖZÜM (araştırmaya dayanıyor, TARAFIMIZCA UÇTAN UCA DOĞRULANMADI - vLLM
# Windows'ta çalışmadığı için test edemedik): stable-ABI geçişinden ÖNCEKİ
# son sürüme sabitleyin. v0.8.3, PyPI'daki bu geçiş öncesi son sürüm.
#
#     uv pip install "vllm==0.8.3" xgrammar --torch-backend=auto
#
# Bu da çalışmazsa: hedef makineniz Linux + Docker ise (Colab değil)
# docker-compose.yml'deki `gpu` profilini deneyin - Docker imajı kendi
# CUDA runtime'ını taşıyor, pip'in sürüm seçimi sorununu tamamen atlıyor:
#
#     docker compose --profile gpu up -d vllm
#
# Bu sonucu bize bildirin - sabitlenen sürüm çalışırsa/çalışmazsa bu dosya
# güncellenmeli.
#
# LINUX GEREKTİRİR. vLLM'in resmi platform listesinde Windows YOK. Windows'ta
# üç seçenek: (1) docker compose --profile gpu up -d vllm, (2) WSL2 içine
# kurup host'tan localhost:8000 ile erişin, (3) ayrı Linux sunucuda çalıştırıp
# VLLM_BASE_URL'i ona yönlendirin.
#

# kalır), caption üretilmez, rerank atlanır.
